Implementazione accesso concorrenza Pallet e Lotto

Obiettivo

È stato introdotto un sistema di gestione della concorrenza per:
-accesso contemporaneo ai pallet
- modifica concorrente dei lotti di produzione
- coordinamento tra interfacce utente e controller automatico

L’obiettivo è evitare:
1. modifiche concorrenti incoerenti sui dati pallet/lotto
2. movimentazioni automatiche mentre un pallet è in modifica
3. blocchi permanenti dovuti a crash delle task

Architettura applicativa

- 7 interfacce tecCellOPE

- controller tecFmsDRV
- tecCell (escluso dalla gestione; sempre abilitate modifiche a pallet e lotti)

- database SQL Server

Modello di concorrenza implementato

La soluzione implementata utilizza:
- lock logico applicativo sui pallet
- ownership del pallet tramite TaskId
- heartbeat delle task
- recovery automatica tramite stored procedure attivate da tecFmsDRV

- controllo concorrenza ottimistica sui lotti tramite rowversion

Stati operativi pallet utilizzati

- Free
- Editing
- ReservedByController (scheduler)
- Moving

Modifiche database

Tabella PALLETS:
- StatoOperativo varchar(30)
- OwnerTaskId uniqueidentifier
- StatoChangedAt datetime2

Tabella Produzione:
- RowVer rowversion

Nuova tabella TaskHeartbeat:
- TaskId
- TaskName
- HostName
- ProcessId
- LastHeartbeat
- IsEnabled

Stored procedure implementate

Gestione pallet:
- usp_Pallet_Release
- usp_Pallet_ReleaseAll
- usp_Pallet_ReleaseAll_AnyTask
- usp_Pallet_SetState
- usp_RecoverDeadTasks

Gestione lotti:
- usp_Lotto_Save_Atomic

- usp_Lotto_Save_ProduzioneMacchineFile

- usp_Lotto_Save_ProduzioneOnly

Table Type SQL Server

- dbo.TvpMacchineEquivalenti
- dbo.TvpPartProgramUpdate

Gestione UI

Ingresso editor:
- chiamata usp_Pallet_SetState con stato = Editing
- acquisizione lock logico

Save:
- esecuzione logica legacy
- controllo RowVersion (per ora non utilizzato)
- rilascio lock tramite usp_Pallet_Release

Chiusura editor:
- rilascio automatico del pallet

Se non è possibile acquisire il lock logico, viene abilitato alla modifica un insieme limitato di caratteristiche del pallet e del lotto

Gestione controller

Scheduler

- chiamata usp_Pallet_SetState con stato = ReservedByController (se non è possibile acquisire il lock - acquisizione lock logico
- schedulazione delle movimentazioni

- rilascio lock tramite usp_Pallet_Release per i pallet non movimentati
- cambio stato ai pallet movimentati settando lo stato Moving con usp_Pallet_SetState

Movimentazioni manuali (da interfaccia)

- acquisizione lock logico con usp_PalletSetState con stato = Moving

Gestione movimentazioni

- rilascio lock tramite usp_Pallet_Release per i pallet dei movimenti completati
- recovery automatica in caso di errore

Inizializzazione

Alla partenza tutti i pallet vengono dichiarati Free

Heartbeat task

Ogni task:
- si registra in TaskHeartbeat
- aggiorna periodicamente LastHeartbeat
- viene marcata come non attiva in caso di chiusura controllata o timeout

Controller – timer che scatta ogni minuto:
- rileva task morte
- libera pallet bloccati

Strategia di migrazione

Per limitare le modifiche al software esistente:
- non sono state riscritte tutte le query legacy
- sono stati intercettati:
- ingresso editor
- save
- uscita editor

La logica legacy continua a funzionare all’interno del lock applicativo.
